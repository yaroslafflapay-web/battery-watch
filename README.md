# Battery watch — уведомление о низком заряде батареи без домашнего сервера

Опрашивает облако DESS Monitor (то же облако, что использует приложение SmartESS),
и шлёт push на iPhone через ntfy.sh, если заряд батареи упал ниже порога.
Всё крутится бесплатно в GitHub Actions — никакого железа дома не требуется.

**Статус этого подхода:** неофициальный. У Eybond/DESS Monitor нет публичного
API для сторонних разработчиков — доступ построен на том же URL, которым
пользуется сам браузер/приложение. Если Eybond изменит формат — придётся
один раз повторить шаг 1.

---

## Шаг 1. Получить DESS_API_URL и заголовок Auth

У актуальной версии платформы (проверено на реальном аккаунте, сентябрь 2026)
запросы идут на домен `api.valueclouds.com`, а авторизация передаётся не
параметрами в самом URL (`sign`/`salt`/`token`), а отдельным HTTP-заголовком
**`Auth`** (похож на JWT-токен, длинная строка вида `eyJhbGci...`). Поэтому
одного URL недостаточно — нужно захватить URL и заголовок вместе.

1. Зайди на https://www.dessmonitor.com в браузере на компьютере и залогинься
   тем же логином/паролем, что используешь в SmartESS.
2. Открой инструменты разработчика (F12) → вкладка **Network** → обнови страницу (F5).
3. Перейди на вкладку **Energyflow** (там, где видно живой % заряда батареи).
4. В списке запросов найди `querySPDeviceLastData?devcode=...&pn=...&devaddr=...&sn=...`
   (там же должны появиться SN/PN твоего устройства, видные и в разделе Alarm info).
5. Кликни правой кнопкой по этому запросу → **Copy → Copy as cURL (bash)**.
6. Из скопированного текста тебе нужны два значения:
   - Сам **Request URL** (из заголовка Headers → General → Request URL) — это `DESS_API_URL`.
   - Значение заголовка **`Auth: ...`** (из Request Headers) — это `DESS_AUTH_HEADER`.

Сохрани оба значения как секреты репозитория (Settings → Secrets and
variables → Actions → New repository secret): `DESS_API_URL` и
`DESS_AUTH_HEADER`.

**Важно:** сделай репозиторий **приватным**. Оба этих значения по сути
равнозначны паролю от твоего аккаунта DESS Monitor — никогда не публикуй их
и не отправляй по незащищённым каналам.

**Открытый вопрос про срок жизни токена:** заголовок `Auth` похож на
JWT-сессионный токен, а не на долгоживущий подписанный URL (как было в
старых версиях платформы, судя по описаниям сообщества). Это значит, что он,
скорее всего, истечёт через какое-то время (часы/дни — неизвестно точно).
Проверь вручную: выполни тот же запрос (например, вставив скопированную
cURL-команду в терминал) через несколько часов и посмотри, отвечает ли он
ещё 200 OK. Если токен живёт недолго — понадобится либо обновлять секрет
вручную с той же периодичностью, либо реализовать автоматический вход по
логину/паролю (это отдельная, более сложная задача, если понадобится).

## Шаг 2. Ключ параметра SOC (SOC_PARAM_ID)

Уже найден и прописан в workflow по умолчанию: **`bt_battery_capacity`**
(группа `bt_`, `"par": "Battery percentage"`, единица `%`) — подтверждено
по реальному ответу API для этого инвертора. Менять не нужно, если только
DESS в будущем не изменит структуру ответа — тогда лог ошибки в Action
распечатает все доступные параметры для повторного поиска.

## Шаг 3. Настроить ntfy на iPhone

1. Установи приложение **ntfy** из App Store.
2. Придумай **длинную случайную строку** для топика (например, сгенерируй
   32 случайных символа) — это и есть твой "адрес" для уведомлений.
   Не используй что-то угадываемое вроде "moy-battery".
3. В приложении ntfy подпишись на этот топик (Subscribe to topic).
4. Сохрани ту же строку как секрет репозитория `NTFY_TOPIC`.

**Про безопасность топика:** ntfy.sh — публичный бесплатный сервер без
авторизации. Топик по факту работает как пароль: кто знает строку — тот
может и читать твои уведомления, и (если настроена кнопка реле, см. ниже)
нажать на неё удалённо. Никогда не публикуй и не коммить эту строку в
открытом виде.

## Шаг 4 (опционально). Кнопка включения реле Shelly

Так как скрипт выполняется в облаке GitHub, а не у тебя дома, единственный
практичный способ управлять Shelly удалённо — через **Shelly Cloud API**,
а не локальный адрес устройства.

1. В приложении Shelly: профиль → Settings → **Authorization Cloud key** —
   сгенерируй Cloud Auth Key, и найди Device ID нужного реле.
2. Собери URL вида:
   `https://<твой-shelly-cloud-сервер>/device/relay/control?id=<DEVICE_ID>&channel=0&turn=on&auth_key=<AUTH_KEY>`
   (сервер вида `shelly-XX-eu.shelly.cloud` — уточни в документации Shelly Cloud API
   под свой регион).
3. Сохрани этот URL как секрет `SHELLY_ACTION_URL`.

**Честная оговорка по безопасности:** кнопка в уведомлении ntfy — это просто
ссылка, зашитая в тело push-сообщения. Она физически видна всем, кто
подписан на твой топик ntfy (см. выше). То есть `SHELLY_ACTION_URL` с твоим
Cloud Auth Key настолько же чувствителен, как и сам ключ. Если это тебя не
устраивает как уровень риска для управления реле сети — не подключай этот
шаг вообще и используй уведомление только как повод самому открыть
приложение Shelly и включить реле руками. Это менее удобно, но не создаёт
удалённо управляемую точку входа с ключом внутри push-уведомления.

## Пороги

По умолчанию: алерт при SOC ≤ 25%, сброс алерта (готовность прислать снова)
при восстановлении SOC ≥ 40%. Меняются прямо в `battery-watch.yml` —
переменные `LOW_THRESHOLD` и `RECOVER_THRESHOLD`.
